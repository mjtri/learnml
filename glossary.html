    Glossary

    Every dotted-underlined word in a lesson opens its definition when tapped. This page is the same list, A–Z, with the lesson that introduced each word.

    -

    --cloud

    The Claude Code flag that starts a new cloud session for the current repository: claude --cloud "task" clones the GitHub remote at your branch, so push first.

    first met in agentic-05/day-2

    /

    /insights

    A Claude Code command that writes an HTML report on how you work: projects, friction points, suggestions. Reads local sessions only; its analysis tokens count against your plan.

    first met in agentic-08/day-1

    /loop

    A Claude Code command that re-runs a prompt on an interval inside the open session. Session-scoped: it stops with the session and expires after seven days.

    first met in agentic-05/day-1

    /plan

    The command that turns on plan mode for the next prompt (Claude Code) or toggles it (Codex): read and propose first, edit only after approval.

    first met in agentic-02/day-2

    @

    @import (also: @imports)

    A line in CLAUDE.md of the form @path that pulls another file into context at launch. Paths resolve relative to the importing file; at most four hops deep.

    first met in agentic-02/day-1

    A

    A/B week (also: A/B weeks)

    One week with a tool installed, logging the same kind of task with and without it: minutes, usage delta, quality 1 to 5. The numbers decide keep or uninstall.

    first met in agentic-09/day-3

    ablation (also: ablations, ablate, ablated, ablating)

    An experiment that removes or replaces one component of a model, keeps everything else fixed, and measures the change in loss, to learn what that component was doing.

    first met in week-06/day-5 · canvas card core-transformer

    ablation study (also: ablation studies)

    A table of runs where you remove or swap one part of your method at a time, keeping everything else fixed, to show which parts carry the gain.

    first met in week-10/day-3 · canvas card build-step6

    accept-edits mode (also: acceptEdits, accept edits mode)

    Claude Code permission mode that runs file edits and simple file commands without asking; other shell commands, the network and paths outside the repo still prompt.

    first met in agentic-03/day-2

    accuracy

    The fraction of examples the model labels correctly. What you report; the loss is what you train on, because accuracy has no useful gradient.

    first met in week-03/day-1 · canvas card core-dl

    activation function (also: activation functions)

    The fixed bend applied to a neuron's weighted sum, such as tanh or ReLU. It has no parameters; it is what stops a stack of layers collapsing into one.

    first met in week-02/day-4 · canvas card core-calc

    Adam (also: AdamW)

    The default optimizer for deep learning. Keeps running averages of each gradient and of its square, then steps each parameter by roughly the learning rate regardless of its gradient's size.

    first met in week-03/day-3 · canvas card core-optim

    adapter (also: adapters, LoRA adapter, LoRA adapters)

    The small set of trained weights added to a frozen model to change its behaviour. Saved alone it is megabytes; swapping adapters swaps tasks without reloading the base model.

    first met in week-08/day-3 · canvas card lin-lora

    adversarial review (also: adversarial reviews)

    A read-only review told to argue against the chosen design and its assumptions, not only hunt bugs. In codex-plugin-cc: /codex:adversarial-review with focus text.

    first met in agentic-04/day-3

    agent (also: agents)

    A model that runs in a loop: read the situation, pick a tool, act, read the result, repeat until a goal is met. Claude Code and Codex are agents.

    first met in agentic-01/day-1

    agent teams (also: agent team)

    An experimental Claude Code mode where a lead session spawns teammate sessions that message each other and share a task list. Each teammate is a full context window.

    first met in agentic-04/day-2

    AGENTS.md

    The cross-tool instruction file convention read by Codex and, when no CLAUDE.md exists, by Claude Code. One source of truth for repo rules.

    first met in agentic-01/day-1

    AgentShield

    A scanner shipped inside ECC that audits an agent setup for leaked secrets, loose permissions, hook injection and risky MCP servers. Useful on its own, without the bundle.

    first met in agentic-09/day-3

    allowed-tools

    A line in a skill's front matter that pre-approves tools for the invoking turn. Read it before running a repository's skills: a skill can grant itself broad access.

    first met in agentic-09/day-1

    allowlist (also: allowlists, allowlisted, allow rule, allow rules)

    Tools or command patterns pre-approved in a settings file, like Bash(git commit *), so they run without a prompt. Deny rules override it in every mode.

    first met in agentic-03/day-2

    alpha (also: lora_alpha, LoRA alpha)

    The gain on a LoRA update: the learned change is multiplied by alpha over rank before being added. Raising it makes the adapter push harder, like a larger learning rate.

    first met in week-08/day-4 · canvas card core-tooling

    analysis script (also: analysis scripts)

    A script in the repo that reads the run log and prints every number a document uses. The chat is a draft; the script is the record.

    first met in agentic-07/day-2

    approval policy (also: approval policies)

    Codex's rule for when it must ask: on-request asks only to step outside the sandbox; never asks nothing. Paired with a sandbox mode that says what commands can touch.

    first met in agentic-03/day-2

    arXiv ID (also: arXiv IDs, arXiv identifier)

    The label of an arXiv preprint: two digits of year, two of month, a dot, then a serial number, like 1706.03762. A month above 12 cannot exist.

    first met in agentic-06/day-1

    attention (also: self-attention, attention head, attention heads)

    A soft lookup: each token asks for what it needs, every token advertises what it has, and the match decides how much of each token's content is mixed in.

    first met in week-04/day-3 · canvas card lin-attention

    attention weights (also: attention weight, attention pattern)

    The numbers that say how much one token looks at each other token: one row per query, every entry at least zero, each row summing to 1.

    first met in week-04/day-3 · canvas card lin-attention

    auto memory (also: auto memories, Codex memories)

    Notes the agent writes for itself across sessions: your preferences, corrections, project facts. Loaded every session but never enforced; Claude Code and Codex both keep them on your machine.

    first met in agentic-02/day-3

    auto mode

    Claude Code permission mode where a separate classifier reviews each action instead of you and blocks risky ones. The starting mode for terminal sessions on recent versions.

    first met in agentic-03/day-2

    autoencoder (also: autoencoders, auto-encoder)

    A network trained to copy its input to its output through a narrow middle, so the middle must keep what matters. An encoder squeezes, a decoder rebuilds.

    first met in week-12/day-2 · canvas card bridge-codec

    autograd

    PyTorch's system that records the computation graph during the forward pass and applies the chain rule for you when you call backward().

    first met in week-01/day-4 · canvas card core-calc

    automation recipe (also: automation recipes)

    A personal automation built from five parts: a data file you edit, a template you replace, a skill that maps one onto the other, an oracle that checks, a trigger.

    first met in agentic-10/day-1

    AutoModel (also: AutoModelForCausalLM)

    The Transformers class that reads a repository's config, builds the right architecture and loads the weights. The ForCausalLM variant adds the next-token output layer.

    first met in week-07/day-2 · canvas card core-tooling

    AutoTokenizer

    The Transformers class that reads a Hub repository's tokenizer files and returns the matching tokenizer: text in, integer token ids and an attention mask out.

    first met in week-07/day-2 · canvas card core-tooling

    axis (also: axes)

    One direction you can index a tensor along, such as rows, columns, colour channels or time. Also called a dimension.

    first met in week-01/day-1 · canvas card core-linalg

    B

    background agent (also: background agents, background session, background sessions)

    A Claude Code session moved off your screen with /bg or claude --bg. It edits inside its own worktree and spends your quota on its own.

    first met in agentic-04/day-2

    backpropagation (also: backprop)

    The backward pass applied to a neural network: the chain rule run from the loss back to every weight, reusing shared work so it costs about one extra forward pass.

    first met in week-01/day-4 · canvas card core-calc

    backward pass

    Walking the computation graph from the output back to the inputs, computing how sensitive the output is to each value on the way.

    first met in week-01/day-4 · canvas card core-calc

    baseline (also: baselines)

    The method B your idea must beat. A result only means something relative to a baseline, and the baseline you choose decides how much it means.

    first met in week-10/day-2 · canvas card build-step5

    batch (also: batches)

    A group of examples processed together, stacked along the first axis. 32 images of shape (3, 64, 64) form a batch of shape (32, 3, 64, 64).

    first met in week-01/day-1

    BatchNorm (also: batch normalization, batch norm, BatchNorm1d)

    A layer that normalizes each unit's output across the current batch, then lets the network re-scale it. Keeps activations well-sized in deep nets; behaves differently at evaluation time.

    first met in week-03/day-5 · canvas card core-dl

    BERT

    Google's 2018 encoder, trained as a masked language model on raw text and then adapted per task. The template for train once, reuse everywhere.

    first met in week-06/day-5 · canvas card lin-bert

    bigram (also: bigrams, bigram model)

    The smallest language model: predict the next token from the current token only. Learnable as a table of counts, one row per current token.

    first met in week-04/day-2 · canvas card core-prob

    bootstrap (also: bootstrapping, bootstrapped, bootstraps, bootstrap resampling)

    Estimate uncertainty by resampling your own results with replacement many times and recomputing the statistic each time. The spread of those recomputations is the uncertainty.

    first met in week-09/day-5 · canvas card core-prob

    bottleneck (also: bottlenecks)

    The narrowest point of a network, where an input must fit into a few numbers. Shape it like a real display and the network learns a code for that display.

    first met in week-12/day-2 · canvas card bridge-codec

    BPE (also: byte-pair encoding, byte pair encoding, Byte-Pair Encoding)

    Byte-pair encoding: build a tokenizer by starting from bytes and repeatedly gluing the most frequent adjacent pair of pieces into one new piece.

    first met in week-06/day-1 · canvas card core-transformer

    broadcasting (also: broadcast, broadcasts)

    The rule that lets tensors of different shapes combine: line shapes up from the right; a size-1 or missing axis is virtually copied to match the other.

    first met in week-01/day-1 · canvas card core-linalg

    budget rule (also: budget rules)

    A written trigger and action for one meter: when this number passes this threshold, do that; with the source or measurement that says the action works.

    first met in agentic-08/day-2

    bypass mode (also: bypassPermissions, bypass permissions mode, bypass permissions)

    Claude Code permission mode that skips prompts and safety checks entirely. For throwaway containers or VMs only; deny rules and a few critical paths still apply.

    first met in agentic-03/day-2

    byte (also: bytes)

    A number from 0 to 255, the unit computers store text in. An English letter is one byte; a Korean syllable is three.

    first met in week-06/day-1 · canvas card core-transformer

    C

    catastrophic forgetting

    When training on a new task overwrites what a model could already do, so old abilities drop sharply. Like a device remapping that erases a user's earlier learned mapping.

    first met in week-08/day-5 · canvas card bridge-adaptation

    causal mask (also: causal masks, causal masking)

    Blanking every score that points to a later token before the softmax, so a token can only mix in its past. Without it, next-token training can read its own answer.

    first met in week-04/day-4 · canvas card core-transformer

    ccusage

    A command that reads the local session logs of Claude Code and Codex and prints daily, weekly or per-session token reports. No hook, no context cost, nothing sent anywhere.

    first met in agentic-09/day-3

    chain rule

    When one quantity affects another through a chain of steps, the overall sensitivity is the product of the step-by-step sensitivities.

    first met in week-01/day-4 · canvas card core-calc

    CHANGELOG (also: CHANGELOG.md, failed approaches)

    The experiment's lab notes: units done, and failed approaches with why they failed and the run that shows it, so no later session retries them.

    first met in agentic-07/day-1

    character-level model (also: character-level models, character-level)

    A language model whose tokens are single characters, so its alphabet is tiny (about 65 symbols) and it must learn spelling before words.

    first met in week-05/day-1 · canvas card core-transformer

    ChatGPT Business (also: Business plan, ChatGPT Business plan)

    OpenAI's team subscription (formerly Team). Seats share one usage pool across ChatGPT and Codex; business data is not used for training by default.

    first met in agentic-01/day-2

    checkpoint (also: checkpoints)

    A saved copy of a model's weights (and often optimizer state) at one moment of training, so a run can be resumed, compared or shared.

    first met in week-05/day-3 · canvas card core-transformer

    checkpoint files

    The files a Hub repository needs to run a model: a config describing the architecture, a weights file, and the tokenizer. Lose one and the others are useless.

    first met in week-07/day-1 · canvas card core-tooling

    Chinchilla

    DeepMind's 2022 result: for a fixed compute budget, grow parameters and training tokens together, roughly 20 tokens per parameter. Earlier large models were under-trained.

    first met in week-06/day-4 · canvas card lin-chinchilla

    citation verification (also: citation check, citation checks, verify pass)

    A separate pass after drafting in which every reference is looked up by DOI or arXiv ID and dropped if no record exists or the record does not match.

    first met in agentic-06/day-3

    CLAUDE.md

    Claude Code's project instruction file, loaded into every session. Keep it short; it can import other files with @path.

    first met in agentic-01/day-1

    CLIP

    OpenAI's 2021 model: an image encoder and a text encoder trained contrastively on 400 million captioned web images, so a picture and its description land close together.

    first met in week-09/day-2 · canvas card lin-clip

    cloud routine (also: cloud routines)

    A saved Claude Code prompt plus repositories that runs as a cloud session whenever a trigger fires, laptop closed, without permission prompts. Research preview; spends your subscription usage.

    first met in agentic-05/day-1

    cloud session (also: cloud sessions, Claude Code on the web)

    Claude Code running on Anthropic's servers against your GitHub repo, started from claude.ai/code or the mobile app.

    first met in agentic-01/day-3

    Codex

    OpenAI's coding agent, available as a CLI, an IDE extension, a desktop app and a cloud service; included in ChatGPT Business.

    first met in agentic-01/day-3

    Codex cloud (also: cloud task, cloud tasks)

    Codex running in an isolated cloud environment on a copy of your repo, started from the web, GitHub or a connected app, finishing in a pull request.

    first met in agentic-01/day-3

    Codex Remote

    Starting, steering and approving Codex on your own computer from the ChatGPT mobile app. The computer must stay awake.

    first met in agentic-01/day-3

    codex-plugin-cc (also: Codex plugin, Codex plugin for Claude Code)

    OpenAI's plugin that runs Codex from inside Claude Code for reviews and delegated tasks. It spends your ChatGPT/Codex usage, not the Claude plan.

    first met in agentic-04/day-3

    Colab

    Google Colaboratory: free hosted Python notebooks in the browser, with an optional GPU. Where the weekly build sessions run.

    first met in week-01/build · canvas card core-tooling

    commit per unit (also: one commit per unit, commit-per-unit)

    One git commit for each finished unit of work, made only after the check passes, so any step can be rolled back and the branch itself records progress.

    first met in agentic-07/day-1

    compaction (also: auto-compaction)

    Summarising the conversation so far to free context. Claude Code does it automatically near the limit; /compact does it on demand.

    first met in agentic-01/day-1

    computation graph (also: computation graphs, computational graph)

    A drawing of a calculation as boxes (operations) joined by arrows (values). PyTorch records one as your code runs.

    first met in week-01/day-4 · canvas card core-calc

    compute budget (also: compute budgets)

    The total training time you allow an experiment, counted in GPU-hours: runs times seeds times minutes per run. Decide it before the first run.

    first met in week-10/day-5 · canvas card build-step6

    compute-optimal (also: compute optimal)

    The model size and amount of training data that give the lowest loss for a fixed training compute budget, rather than the biggest model you can afford.

    first met in week-06/day-4 · canvas card lin-chinchilla

    confidence interval (also: confidence intervals)

    A range around a measured number that would contain the true value most of the time if the experiment were repeated. Reported as low to high, never one number.

    first met in week-09/day-5 · canvas card core-prob

    config (also: configs)

    The list of settings that decide what a model or a run is: layer count, width, vocabulary size for a model; seed, learning rate, data size for a run.

    first met in week-07/day-2 · canvas card core-tooling

    config file (also: config files)

    The file of settings the entry point reads, whose values overwrite its defaults. Every setting in it is either a checklist line or a detail the paper left out.

    first met in week-11/day-3 · canvas card core-tooling

    confusion matrix (also: confusion matrices, confusion table, confusion tables)

    A table with one row per stimulus shown and one column per answer given, counting each combination. The off-diagonal cells are the confusions a display causes.

    first met in week-12/day-4 · canvas card build-step7

    context length (also: context lengths, block size)

    How many previous tokens a model may look at when predicting the next one. A bigram has 1; a transformer has a fixed maximum set by its position table.

    first met in week-04/day-2 · canvas card core-prob

    context window (also: context windows)

    Everything the model can see at once: instructions, your messages, tool results, files it read. Finite, and the main thing you spend.

    first met in agentic-01/day-1

    contrastive learning (also: contrastive, contrastive loss, contrastive objective)

    Training without labels by asking the model to tell matching pairs from non-matching ones: pull true partners together, push everything else in the batch apart.

    first met in week-09/day-1 · canvas card lin-cpc

    control condition (also: control conditions)

    A run that differs from your method in exactly one thing. Like a control condition in a user study: it makes a difference attributable to one cause.

    first met in week-10/day-3 · canvas card build-step6

    converge (also: converges, converged, convergence)

    To settle down: the loss stops improving meaningfully because the parameters have reached a low point.

    first met in week-01/day-5 · canvas card core-optim

    cosine similarity (also: cosine)

    The dot product of two vectors after dividing out their lengths: 1 means same direction, 0 unrelated, minus 1 opposite. Length no longer matters.

    first met in week-04/day-1 · canvas card lin-word2vec

    cross-entropy (also: cross entropy)

    The standard classification loss: how surprised the model is by the correct label, averaged over examples. Zero when it was certain and right; large when confident and wrong.

    first met in week-03/day-2 · canvas card core-optim

    D

    data file (also: data files)

    The one file you type per run of a recipe: plain text, one key per fact, kept outside every repository because it holds your personal details.

    first met in agentic-10/day-1

    data flow (also: data flows)

    The path examples take from a file on disk through loading, preprocessing and the model to the line that computes the metric. Read it backwards from the metric.

    first met in week-11/day-3 · canvas card core-tooling

    data leakage

    When information from the test data reaches training, through duplicates, shared sources or the answers themselves, so a score looks far better than the model really is.

    first met in week-08/day-5 · canvas card bridge-adaptation

    DataLoader (also: DataLoaders, data loader)

    The PyTorch helper that pulls examples from a Dataset, shuffles them and stacks them into batches, one batch per loop iteration.

    first met in week-03/day-1 · canvas card core-tooling

    Dataset (also: dataset, datasets)

    A collection of examples. In PyTorch, a class that answers two questions: how many examples are there, and give me example number i.

    first met in week-03/day-1 · canvas card core-tooling
