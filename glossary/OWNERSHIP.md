# Term ownership and visual topics per week

Generation agents read this. A term is **defined once**, in the week that first needs it (its "owner"), in that
week's shard `glossary/terms-<week-dir>.jsonl`. Every other week uses the term without redefining it. If a week needs a
term owned by a *later* week, it uses plain words instead (or the later week's owner is moved here first).
Terms in `terms-core.jsonl` (`low rank`, `LoRA`, `MCP`, `worktree`) are pre-defined forward references; the owning week
below replaces the core row with a full definition in its own shard and deletes the core row (integration handles it).

Visual topics are reserved per week so no two weeks build the same interactive.

## Reserved cross-track notes
- "token" is defined in B1 (`terms-agentic-01.jsonl`). A4 must reference it, not redefine it. A4 owns "context length" and "sequence".
- "MCP" and "worktree" are core rows; B6 (MCP as connector) and B4 (worktree) replace them with full definitions.
- "hook", "skill", "routine" were deliberately removed from B1 because they collide with ordinary English; B3/B4/B5 define them with aliases that avoid the bare word where possible (e.g. term "hook" with no plural alias, and prose says "a Claude Code hook").
