    Playbook

    Your working rules for Claude Code (Max 20x) and ChatGPT Business (chat + Codex). This page is the ledger for Track B: each lesson ends with a prompt to add one line here. Keep it short: a rule earns its place by a source or a measurement, and gets deleted when it stops being true. Target ≤ 20 rules by week B8.

    Format: - rule — evidence (date). Evidence is a link, or a number you measured in an apply task.

    Seed rules (from official guidance, checked 2026-09-27)

    These ten appear in several official sources at once. Keep, edit or delete them as your own evidence comes in.

    1. Give the agent a check it can run: a test, a build, a checker, a "done when" it can evaluate itself. — Claude Code best practices, Codex best practices
    2. Explore, then plan, then code. Skip the plan only for one-line diffs. — Claude Code best practices, Codex best practices
    3. Keep one short, durable instruction file (AGENTS.md, imported by CLAUDE.md) and prune it. — Memory docs, AGENTS.md docs
    4. Context is the scarce resource: load it just in time; /clear or restart instead of piling on corrections. — Effective context engineering
    5. Hand research and noisy output to subagents that return summaries. — Claude Code best practices
    6. Keep a progress file and commit after each unit of work. — Effective harnesses for long-running agents
    7. Separate the doer from the grader: review with a different agent, ideally a different vendor. — codex-plugin-cc (OpenAI-maintained plugin for Claude Code), Code review
    8. Start with tight permissions or a sandbox; loosen only for trusted repos. — Permission modes, Codex sandboxing
    9. Few, well-described tools; prefer a CLI the agent can call over a heavy MCP server. — Writing effective tools for agents (few tools), Manage costs (CLI over MCP)
    10. Start with the simplest thing; automate a task only once the manual version runs reliably. — Building effective agents, Codex best practices
